# Discussion turns: each question plain, brief, and on its own

## When to Apply
Any back-and-forth turn that needs my call: scope's Discuss, plan's open calls, a workflow gate,
walking through review comments, or any design discussion.

## Rule
- **One numbered item per question:** the question in one sentence, the minimum context to answer
  it (a few lines), your recommendation. Then the next question. Never weave several questions
  into one paragraph.
- **Findings serve a question.** Research, damage analysis and options appear inside the question
  they bear on, never as their own block. A finding that bears on no open question waits.
- **Ask only what blocks the next step.** Questions that only arise from my answers come in the
  next turn.
- **Answering me:** ≤5 lines, one point, no tables. Depth only when I ask for it ("explain in more
  detail", "deep dive").
- A skill's own report format (address-comments' numbered report, pr-review's tiers) still wins
  for that report; this governs the discussion around it.

## Why
A scope reply that packed findings, four options and several new questions into one message was
unreadable: "I can't keep up with this or read the questions." Questions skipped or answered wrong
at that checkpoint carry straight into the plan.

This applies across all sessions working in this workspace.
